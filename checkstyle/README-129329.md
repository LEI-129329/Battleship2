# Checkstyle — 129329

**Aluno:** 129329 — Luís Aguiar de Sousa

## Objetivo

Configurar e integrar o Checkstyle no GitHub Actions para verificar automaticamente a convenção de nomenclatura dos parâmetros em código Java, durante os Pull Requests dirigidos à branch `main`.

## Regra selecionada

Foi selecionada a regra **`ParameterName`**, que verifica os nomes dos parâmetros de métodos e construtores.

A convenção adotada é **lowerCamelCase**: os identificadores começam com uma letra minúscula e as palavras seguintes são distinguidas por maiúsculas, sem espaços ou underscores.

Exemplos:
- Válido: `targetRow`, `playerName`
- Inválido: `TargetRow`, `target_row`, `Other_Position`

## Configuração

A configuração encontra-se em `checkstyle/checkstyle-129329.xml`.

A expressão regular utilizada é:

```regex
^[a-z][a-zA-Z0-9]*$
```

O workflow GitHub Actions encontra-se em `.github/workflows/checkstyle-129329.yml` e utiliza a Action [Checkstyle for Java](https://github.com/marketplace/actions/checkstyle-for-java).

O parâmetro `filter_mode: added` limita a publicação de violações às linhas adicionadas no Pull Request, evitando que ocorrências preexistentes em linhas não alteradas bloqueiem esta experiência.

## Limitações do Checkstyle

O Checkstyle permite verificar automaticamente se os identificadores respeitam convenções sintáticas de nomenclatura, mas não consegue determinar se um nome é semanticamente significativo ou suficientemente descritivo. Assim, um identificador pode respeitar a expressão regular definida e, ainda assim, ser pouco claro ou inadequado ao contexto do programa.
